# แผนสร้างระบบจัดการปูใหม่ (v2) — สำหรับขายให้คนเลี้ยงปู

## Context
ระบบเดิม (v1) สร้างไว้ใช้เองในกลุ่ม ใช้มา 5 เดือนแล้วเจอปัญหาหลายอย่าง: มีเมนู 20 กว่าเมนูจนหาไม่เจอ, ตั้งค่าแจ้งเตือนยาก (เพื่อนที่ลองใช้ไม่ใช้เลย), ลืมใส่ต้นทุนล็อตจนไม่อยากใช้หน้าขาย, ป๊อปอัปปูทำให้วันที่ในประวัติผิด, หน้ารายงานงงที่สุด, คลังสาร/คลังของซ้ำซ้อนกัน, แอนิเมชันทำให้มือถือร้อน
เป้าหมาย v2: ระบบที่ **ขายได้** (รายเดือน/รายปี/ซื้อขาด ต้องจ่ายก่อนถึงใช้ได้), **เด็ก 6 ขวบก็ใช้ได้** (เมนูน้อย ตัวหนังสือน้อย มีป้าย ⚠ พาไปจุดที่ต้องทำ), **เน้นแจ้งเตือน** และล้างข้อมูลเก่าทิ้ง เริ่มใหม่จาก 0

## การตัดสินใจหลัก (ตอบแล้ว)
| เรื่อง | เลือก |
|---|---|
| Demo | **โค้ดหน้าเว็บชุดเดียว build ได้ 2 แบบ** — `build` (ตัวจริง ยิง API) / `build:demo` (ข้อมูลฟาร์มตัวอย่างในเครื่อง กดเล่นได้ รีเฟรชแล้วรีเซ็ต) แล้วเอาไปวางคนละโดเมน |
| ฐานข้อมูล | **สร้าง DB ใหม่** schema ใหม่ทั้งหมด · DB เก่าเก็บไว้เป็นสำรอง และระบบเดิมใช้งานต่อได้จนถึงวันย้าย |
| หน้าตา | **Sakai + PrimeVue 4 (Aura) + Tailwind + Kanit แบบเดียวกับ `vue-quest-web`** — sidebar เป็นการ์ดลอยด้านซ้าย ชื่อกลุ่มตัวเล็ก เมนูมีไอคอน+ตัวใหญ่ ไม่มีย่อ-ขยายกลุ่ม · **สีหลักเปลี่ยนเป็นฟ้าอมเขียว (teal)** แทนสีส้ม |
| การจ่ายเงิน | **อัปสลิปในระบบ + แอดมินกดอนุมัติ** (QR พร้อมเพย์ + ปุ่มทัก LINE/Facebook อยู่บนหน้ารอเปิดใช้งาน) |

เรื่องเล็กที่ผมตัดสินใจไปก่อน (ถ้าไม่เห็นด้วยบอกได้ครับ):
- **น้ำหนักเก็บเป็นกรัมช่องเดียว** แล้วแปลงตอนแสดงผลตามหน่วยที่ผู้ใช้เลือก — 1 ขีด = 100 กรัมเสมอ ถ้าเก็บ 2 ช่องอาจได้ค่าไม่ตรงกันสักวัน (ผลที่ผู้ใช้เห็นเหมือนที่ขอทุกอย่าง: กดสลับ ขีด/กรัม ที่ช่องกรอกได้ แล้วเปลี่ยนทั้งระบบ)
- หน้าเว็บเขียนด้วย **TypeScript** (เหมือน farmland-web เดิม ไม่ใช้ JS แบบ Quest) เพราะ logic ปู/ให้อาหาร/บัญชีซับซ้อน
- เก็บ backend เดิม (Express + Prisma + MySQL + Plesk) แล้วเขียน schema/service ใหม่ทับในที่เดิม

## 1. โครงสร้าง repo / การ deploy
- **ขั้นแรก: เก็บ v1 ไว้ก่อน** — ทั้ง 2 repo มีงานที่ยังไม่ commit ค้างอยู่เยอะ (farmland-web มี commit เดียวคือ "first commit" แล้วที่เหลือยังไม่ commit ทั้งหมด, backend ยังไม่ commit งาน AI ไข่) → commit + tag `v1-final` ทั้ง 2 repo แล้วแตก branch `v2`
- **Backend `express-farmland` (branch v2):** schema ใหม่ + ลบโฟลเดอร์ migrations เดิม (ยังอยู่ใน tag v1) → migration เดียว `init_v2` ลง DB ใหม่
- **Frontend `farmland-web` (branch v2):** เริ่มใหม่จากโครง Sakai (ไม่เอา Vuetify) · ชั้น `src/api/` มี 2 ตัวที่ใช้ร่วม interface เดียวกัน: `http/` (ตัวจริง) กับ `mock/` (demo: เก็บข้อมูลในหน่วยความจำ ข้อมูลตั้งต้นจากไฟล์ฟาร์มตัวอย่าง) — เลือกตอน build ด้วย `VITE_API_MODE` · เพิ่ม mock ไปพร้อมกับฟีเจอร์ทุกเฟส demo จะได้ไม่ตามหลัง
- **โดเมน:** v2 ขึ้น subdomain ใหม่ไปก่อน (app / api / demo) → ทดสอบจนพอใจแล้วค่อยย้ายจริง · ⚠️ บทเรียนเดิม: โดเมน API ต้อง**ปิด** Proxy mode (WebSocket), โดเมนหน้าเว็บต้อง**เปิด** (`.htaccess` ของ SPA)
- CLAUDE.md ตอนนี้มีแต่ประวัติ v1 → ย้ายไปเก็บที่ `docs/v1-notes.md` แล้วเขียน CLAUDE.md ใหม่สำหรับ v2

## 2. สิทธิ์ใช้งานและการจ่ายเงิน (ข้อ 5.1)
- สมัคร/ล็อกอินได้ทุกคน (อีเมล, Google, LINE, **Facebook ใหม่**) แต่ถ้ายังไม่มีแพ็กเกจที่ใช้ได้ → เข้าได้แค่ **หน้า "รอเปิดใช้งาน"**: การ์ดแพ็กเกจ (เดือน/ปี/ซื้อขาด), QR พร้อมเพย์ (สร้างจากเลขพร้อมเพย์ที่ตั้งใน back office), ปุ่มอัปสลิป, ปุ่มทัก LINE/Facebook, ลิงก์ "ลองดูเดโมก่อน"
- แอดมินเห็นสลิปใน back office → กดอนุมัติ → สิทธิ์เปิดทันที (ส่งอีเมล + แจ้งในระบบ) · แอดมินให้สิทธิ์เองโดยไม่มีสลิปก็ได้ (ทดลองใช้ / เพื่อน)
- ใกล้หมดอายุ: เตือนก่อน 7 วัน และ 1 วัน · หมดอายุแล้วให้เวลา 3 วัน จากนั้นกลับไปหน้ารอเปิดใช้งาน (ข้อมูลยังอยู่ครบ ต่ออายุแล้วใช้ต่อได้)
- BE: middleware `requireActiveSubscription` ครอบทุก route ของฟาร์ม · ข้ามได้เฉพาะ auth / ข้อมูลของฉัน / แพ็กเกจ+สลิป / ประกาศ / แจ้งบัค · ADMIN ข้ามได้หมด
- Facebook login: เพิ่ม provider ใน `src/services/oauth.service.ts` (โค้ดแบบเดียวกับ Google) · Facebook บังคับให้มีหน้า **นโยบายความเป็นส่วนตัว** + **ขั้นตอนลบข้อมูล** → ทำเป็นหน้า public 2 หน้า (ใช้ตอนขายด้วยอยู่แล้ว)

## 3. เมนูใหม่ (จาก 20+ เหลือ 9)
```
ฟาร์มของฉัน          หน้าแรก · กล่องปู · น้ำ · อาหารปู · แจ้งเตือน
เงิน                 บัญชี
อื่นๆ                ประวัติปู · หมู่บ้านฟาร์ม · สอนใช้งาน · ไอเดีย & แจ้งปัญหา
หลังบ้าน (แอดมิน)    ภาพรวม · ผู้ใช้ & สิทธิ์ · สลิปรอตรวจ · บัค · ไอเดีย · ประกาศ · คลิปสอน · ตั้งค่าร้าน
```
- **ตัดเมนู:** ปฏิทิน, การแจ้งเตือนตามรอบ (รวมเข้า "แจ้งเตือน"), สูตรปรุงน้ำ (รวมเข้า "น้ำ"), คลังสาร, คลังของ (เหลือแค่ "อาหารปู"), คู่ค้า & ขายปู (ย้ายไปขายในหน้ากล่องปู), รายงาน (เหลือรายงานบัญชีในหน้า "บัญชี"), วิเคราะห์อาหาร (เป็นการ์ดบนหน้าแรก), พัฒนาการปู + ประวัติปูทั้งหมด (รวมเป็น "ประวัติปู" มี 2 แท็บ), การตั้งค่า (ย้ายไปอยู่ในแต่ละเมนูแล้ว)
- topbar: **ตัวเลือกระบบปู** ("ระบบข้างบ้าน ▾" ข้างในมีปุ่ม "+ เพิ่มระบบปู" — แก้ข้อ 4.6.6) · กระดิ่ง · รูปโปรไฟล์ (ข้างในมี อีเมลรับแจ้งเตือน / หน่วยน้ำหนัก / ธีม / เสียง)
- ทั้งระบบใช้ฟอนต์ Kanit, ขนาดตัวอักษรเริ่มที่ 16px, พื้นการ์ดทึบ (ไม่โปร่งแสง), สมัครใหม่ได้ **ธีมมืดเป็นค่าเริ่มต้น** (ข้อ 4.2), ไม่มีแอนิเมชันหนัก (ห้ามใช้ `backdrop-filter`, ใช้แค่ transform/opacity, ปิดให้เองถ้าเครื่องตั้ง reduced-motion)

## 4. ป้าย ⚠ นำทาง (ข้อ 2.2 / 4.13 / 4.6.3) — ใช้ทั้งระบบ
- BE `GET /api/attention` คืนรายการ "สิ่งที่ต้องทำ/ต้องตั้งค่า" จากที่เดียว เช่น `feeding_plan_missing`, `lot_cost_missing`, `notify_email_missing`, `feed_stock_missing`, `feed_low`, `egg_pct_missing`, `water_targets_missing`, `urgent_task_overdue` — แต่ละรายการบอกว่าอยู่เมนูไหน ปุ่มไหน ข้อความสั้นๆ ว่าอะไร
- FE ทำ 3 ชั้นจากข้อมูลชุดเดียวกัน:
  1. **สามเหลี่ยม ⚠ กะพริบเบาๆ** ที่เมนูใน sidebar และที่ปุ่มเป้าหมาย (component `<AttentionMark k="...">` ครอบปุ่ม)
  2. **กล่องข้อความชี้ไปที่ปุ่ม** ("ยังไม่ได้ตั้งแผนให้อาหาร แตะตรงนี้ 👆") ขึ้นครั้งแรก กดปิดได้ ส่วน ⚠ ยังอยู่จนกว่าจะทำ
  3. **รายการ "เริ่มต้นใช้งาน"** บนหน้าแรก มีหลอดคืบหน้า: สร้างระบบปู → ตั้งค่าน้ำ → ตั้งแผนให้อาหาร → ใส่สต็อกอาหาร → รับปูล็อตแรก → ใส่อีเมล
- ข้อ 4.6.3 (ยังไม่ตั้งแผนให้อาหาร) = ใช้ทั้ง 3 ชั้นนี้

## 5. รายละเอียดทีละหน้า (คำตอบและไอเดียตามที่ถามมา)

### 5.1 แจ้งเตือน (ข้อ 4.4, 4.5, 5.8) — หน้าเดียว 3 แท็บ: `วันนี้ (3)` · `ปฏิทิน` · `ตั้งค่าเตือน`
- **ทำไม่ให้รก (4.4.1):** แท็บ "วันนี้" เป็นการ์ดงาน แบ่งกลุ่ม 🔴 ด่วนมาก / 🟠 ปานกลาง / 🟢 ทั่วไป · การ์ดมีไอคอน + ชื่อ + "เลยมา 2 วัน" + ปุ่มใหญ่ปุ่มเดียว **"ทำเลย"** (พาไปหน้าที่ต้องบันทึก เช่น หน้าน้ำ) หรือ "เสร็จแล้ว" · ที่การ์ดมีเฟือง ⚙ เล็กๆ กดแล้วเปิดตั้งค่าของงานนั้นจากด้านล่างจอ = ไม่ต้องย้ายไปหน้าอื่น
- แท็บ "ตั้งค่าเตือน": แถวละเรื่อง มีสวิตช์เปิด/ปิด + "ทุก 4 วัน · 20:00" + จุดสีความสำคัญ · หน้าแก้ไขใช้ปุ่มชิปทั้งหมด (ทุก N วัน ปุ่ม −/+ หรือเลือกวันในสัปดาห์, ความสำคัญเป็นปุ่มใหญ่ 3 ปุ่ม) · "+ เตือนเรื่องใหม่" มีแบบสำเร็จรูปให้เลือก
- **รายการเริ่มต้น 6 เรื่อง (4.4.4)** สร้างให้อัตโนมัติตอนสร้างระบบปู มี 🔒 ลบไม่ได้ ได้แค่ปิด/ปรับรอบ/ปรับความสำคัญ:
  | เรื่อง | รอบ | ความสำคัญ | ผูกกับ / ปิดงานเมื่อ |
  |---|---|---|---|
  | วัดค่าน้ำ | ทุก 4 วัน | ด่วนมาก | บันทึกค่าน้ำ → ปิดเอง |
  | รอบให้อาหาร | ตามแผนให้อาหาร | ด่วนมาก | ปิดรอบให้อาหาร → ปิดเอง |
  | เช็คเนื้อ/ไข่ปู | ทุก 3 สัปดาห์ | ต่ำ | ปิดเองเมื่อเช็คปูที่ถึงรอบครบ (หรือกดเสร็จ) |
  | ใส่จุลินทรีย์ | ทุก 4 วัน | ปานกลาง | กดเสร็จแล้ว |
  | เติมน้ำจืด | ทุก 3 วัน | ด่วนมาก | กดเสร็จแล้ว |
  | เปลี่ยนใยกรองละเอียด | ทุก 5 วัน | ต่ำ | กดเสร็จแล้ว |
- **ป๊อปอัปเรื่องด่วน (4.4.2):** ถ้ามีงาน "ด่วนมาก" เลยกำหนด → เด้งตอนเปิดแอป/ล็อกอิน แล้ว**เด้งซ้ำทุก 1 ชั่วโมง** ระหว่างใช้งาน (เวลาเปลี่ยนหน้าจะเช็คว่าครบชั่วโมงหรือยัง) พร้อมเสียงเตือนสั้นๆ (ปิดเสียงได้ในโปรไฟล์) · ปุ่ม "ไปทำเลย" / "เตือนอีกครั้งใน 1 ชม." — **ไม่มีปุ่มปิดถาวร** ต้องทำงานให้เสร็จ หรือไปลดระดับความสำคัญเอง (ถ้ามีปุ่มปิดถาวรก็จะกลับไปไม่ทำเหมือนเดิม)
- **อีเมลทุก 4 ชม. (4.4.3 / 5.8):** ใช่ครับ ต้องแก้ Plesk **ครั้งเดียว** — ตอนนี้ Scheduled Task ยิงวันละครั้งตอน 12:30 → เปลี่ยนเป็น**ทุก 15 นาที** แล้วให้แอปเป็นคนเลือกเวลาส่งเอง (ค่าเริ่มต้น 08:00 / 12:00 / 16:00 / 20:00 ผู้ใช้ปรับได้ + ไม่ส่งตอนกลางคืน) ต่อไปจะเปลี่ยนเวลาก็ไม่ต้องเข้า Plesk อีก
- **ประวัติ (4.4.6):** แต่ละเรื่องมีแถบจุดย้อนหลัง (เขียว=ตรงเวลา, ส้ม=ช้า, เทา=ข้าม) + รายการ "ทำเมื่อ วันอังคารที่ 4 พ.ย. 69 (ช้า 1 วัน)"
- **ปฏิทิน (4.5)** = แท็บในหน้านี้ ใช้ FullCalendar ต่อ (ไม่ขึ้นกับ Vuetify)
- เสริมทีหลัง (ไม่อยู่ในรอบแรก): ติดตั้งเป็นแอปบนมือถือ (PWA) + Web Push ให้มีเสียงแจ้งเตือนแม้ไม่ได้เปิดเว็บ

### 5.2 กล่องปู (ข้อ 4.6)
- **ดีไซน์ใหม่ (4.6.1–4.6.2, 4.6.9):** การ์ดทึบ ไม่มีปูเดิน ตัวหนังสือน้อย ช่องกล่องโชว์แค่ จุดสีเคเบิ้ลไทล์ + น้ำหนัก + แถบ % ไข่ + "32 วัน" (**นับจากวันรับปูเข้าล็อต** — ข้อ 4.6.12) · ป้ายเล็กบนกล่อง: ⚠ ถึงรอบเช็ค / 🔖 จอง
- แถบบน: สถานะน้ำ **"✓ น้ำปกติ"** หรือ **"⚠ Mg ต่ำ · pH สูง"** โชว์เฉพาะตัวที่หลุด (4.6.10) · แถบรอบให้อาหาร (ดู 5.4)
- ปุ่มหลักด้านล่างจอ (มือถือ) 3 ปุ่ม: **➕ รับปูเข้า** · **🍤 ให้อาหาร** · **💰 ขายปู**
- **รูปแบบระบบ (4.6.14):** ตอนสร้างระบบเลือกจากรูป 3 แบบ: ตะกร้าดำ / คอนโดด้านเดียว / คอนโดหน้า-หลัง → ใส่จำนวนชั้น×จำนวนช่อง · แบบหน้า-หลังมีแท็บ **"ด้านหน้า | ด้านหลัง"** + รูปผังเล็กบอกว่ากำลังดูด้านไหน ไม่ต้องแบะต่อกันเป็นแถวยาว · ตะกร้าดำโชว์เป็นช่องกลม
- ตัด "ปูที่ถูกจอง" แบบเดิมออก (4.6.11) → เหลือการจองแบบเดียว คือจองจากโหมดขาย (5.6) เลยตรงกันทุกหน้า
- อีเมลแจ้งเตือน (4.6.7) ย้ายไปไว้ในโปรไฟล์ **เว้นว่าง = ไม่ส่งอีเมล** · ถ้ายังไม่ใส่จะขึ้น ⚠ ที่รูปโปรไฟล์ + อยู่ในรายการเริ่มต้นใช้งาน · ถ้าล็อกอินด้วย Google จะถามว่า "ใช้ xxx@gmail.com ไหม? [ใช้เลย]" กดครั้งเดียวจบ

### 5.3 ล็อตปู (ข้อ 4.6.4, 4.6.5, 4.14.3)
- **ปัญหาจริงคือ "ลืม"** → ใช้ 3 อย่างพร้อมกัน: (1) **ปูทุกตัวต้องอยู่ในล็อต** (2) ล็อตที่ยังไม่มีราคามี ⚠ ตลอด + **งานอัตโนมัติ "ใส่ราคาล็อต วันจันทร์ที่ 3 พ.ย."** อยู่ในหน้าแจ้งเตือน (ปิดเองตอนใส่ราคา) (3) ตอนขาย ถ้าเจอปูจากล็อตที่ไม่มีราคา ขึ้นข้อความเตือน + ช่องใส่ราคาตรงนั้นเลย (ไม่บังคับ ไม่ขวางการขาย)
- **ปุ่มเดียว "➕ รับปูเข้า" (4.6.5):** ตัดปุ่ม "จัดล็อตย้อนหลัง" ทิ้งได้เลย เพราะเริ่มจาก 0 ปูทุกตัวจะเข้าผ่านล็อตตั้งแต่แรก
  1. หน้าเดียว: ซื้อจากใคร (เลือก หรือ + เพิ่มใหม่ตรงนั้น) · วันที่รับ ("วันนี้ วันเสาร์ที่ 8 พ.ย.") · ราคาทั้งล็อต (มีปุ่ม "ยังไม่รู้ ใส่ทีหลัง")
  2. แตะกล่องบนผัง → การ์ดเล็ก: รูป / น้ำหนัก / % ไข่ (AI เติมให้) / สีเคเบิ้ลไทล์ → บันทึก → ไปกล่องถัดไปเอง
  3. สรุป: "รับปู 12 ตัว น้ำหนักรวม 3.2 กก." + ถ้ายังไม่ใส่ราคา "⚠ ระบบจะเตือนทุกวันจนกว่าจะใส่ราคา"
- ถ้าเพิ่มปูจากในกล่องโดยตรง → ถามว่า "มาจากล็อตไหน" (เลือกล็อตล่าสุดไว้ให้แล้ว หรือ "ล็อตใหม่")
- ใส่ราคาแล้วแบ่งต้นทุนให้ปูแต่ละตัวตามน้ำหนักเอง (ใช้ลอจิก `splitByWeight` เดิม — ยกเศษให้ตัวสุดท้าย)

### 5.4 ป๊อปอัปปู (ข้อ 4.6.13)
- **แยก "เช็ควันนี้" ออกจาก "แก้ข้อมูล" (4.6.13.1):** ด้านบนเป็นการ์ด "ล่าสุด" (รูป, น้ำหนัก, % ไข่, "เช็คล่าสุด วันอังคารที่ 4 พ.ย. (4 วันก่อน)") อ่านอย่างเดียว · ปุ่มใหญ่ **"📷 เช็ควันนี้"** = เพิ่มรอบเช็คใหม่ที่**ลงวันที่วันนี้อัตโนมัติ** (มีลิงก์เล็ก "ไม่ใช่วันนี้?") — ไม่มีช่องวันที่เก่าให้ลืมเปลี่ยนอีกแล้ว · ปุ่มรอง "✏️ แก้ข้อมูลปู" (ชื่อ/ชนิด/เพศ/เกรด/สี), ย้ายกล่อง, ปูตาย, ลบ · ไทม์ไลน์ประวัติเป็นการ์ดมีรูป จะแก้รอบเก่าต้องกด "แก้รอบนี้" ที่รอบนั้นตรงๆ
- **ชื่อปู (4.6.13.2):** ค่าเริ่มต้น = รหัสกล่อง (เช่น "A1") ชื่อซ้ำกันได้ · รหัสปูไม่ซ้ำสร้างให้เองและซ่อนไว้
- **หน่วยน้ำหนัก (4.6.13.3):** ช่องกรอกมีปุ่มสลับ `ขีด | กรัม` ติดอยู่ กดแล้วเปลี่ยนทั้งระบบ (จำไว้ในค่าผู้ใช้) · เก็บเป็นกรัม
- **ลืม % ไข่ (4.6.13.4):** ใส่รูปใหม่แล้ว **ปุ่มบันทึกจะกดไม่ได้จนกว่าจะมี % ไข่** + ช่องกะพริบ "มีรูปใหม่แล้ว ใส่ % ไข่ด้วย" · AI ประเมิน % จากรูปเติมให้ (ใช้ `eggEstimate.service.ts` ที่ทำไว้เดือนที่แล้ว) = ปกติแค่กดยืนยัน · ⚠️ ลูกค้าใหม่ไม่มีรูปตัวอย่างของฟาร์มตัวเอง → ทำโหมดเริ่มต้นที่ประเมินได้โดยไม่ต้องมีรูปตัวอย่าง (เชื่อได้น้อยกว่า) แล้วค่อยใช้รูปของฟาร์มเมื่อมีพอ
- ปุ่มทุกปุ่มสูงอย่างน้อย 44px, แบ่งเป็นช่วงชัดเจน (4.6.13.5)
- ชนิดปู: **ปูไข่ / ปูเนื้อ / ปูนิ่ม** (ตัด "ไม่ระบุ") (4.6.13.6) · ชนิด/เพศ/เกรดที่เลือกล่าสุด = ค่าเริ่มต้นของปูตัวถัดไป (4.6.13.7)
- **ตัวดูรูป (4.6.13.8, 4.7.2, 4.7.3) ใช้ทั้งระบบ:** ลูกศรซ้าย-ขวา/ปัดนิ้ว · ปุ่มแว่นขยาย + ถ่างนิ้วซูมได้**เฉพาะในรูป** (หน้าเว็บไม่ขยายตาม) · มุมซ้ายบนบอก "กล่อง A1 · ชื่อปู · เช็ควันอังคารที่ 4 พ.ย. · 1.6 ขีด · ไข่ 70%"

### 5.5 อาหารปู + รอบให้อาหาร (ข้อ 4.6.8, 4.12.2)
- **เมนู "อาหารปู"** มีแผนให้อาหาร + สต็อกอาหาร (แทนคลังสาร/คลังของที่ใช้ยาก)
  - **สต็อก:** ค่าเริ่มต้นมี "ปลา" กับ "หอย" (หน่วย **ชิ้น**) เพิ่มชนิดเองได้ · "+ ซื้ออาหาร" ใส่จำนวน (ราคาไม่ใส่ก็ได้ ถ้าใส่ลงบัญชีให้เอง) · ไม่บังคับใส่สต็อก แต่ถ้ายังไม่ใส่จะขึ้น ⚠ · ปิดรอบให้อาหารแล้ว**ตัดสต็อกเอง** · โชว์ **"พออีก 3 รอบ"** แทนตัวเลขเกณฑ์ที่ต้องตั้งเอง · เหลือน้อยกว่า 2 รอบ → งานแจ้งเตือนระดับปานกลาง
  - **แผน (4.6.8.4):** วงรอบวันเหมือนเดิม (วันเว้นวัน / 2 เว้น 1 …) + **แผนอาหาร** ค่าเริ่มต้น "ปลา 1 ชิ้น/ตัว" มีแบบให้เลือก: ปลาอย่างเดียว / หอยอย่างเดียว / สลับปลา-หอย / กำหนดเองรายวัน (ดูล่วงหน้า 14 วัน แตะวันไหนก็เปลี่ยนได้)
- **ถึงรอบ:** แถบ "🍤 วันนี้ ปลา 1 ชิ้น/ตัว (ใช้ 72 ชิ้น)" ถ้าสต็อกไม่พอ: "⚠ หอยมี 10 ต้องใช้ 30 → ให้ปลาแทนไหม? [เปลี่ยนเป็นปลา]" · **แบ่งกล่องได้** (ลากเลือกช่วงกล่องบนผัง เช่น A1–A20 ปลา A21–A40 หอย) → เก็บอาหารเป็นรายตัว ไม่ใช่รายรอบ (ใช้ในการวิเคราะห์ 5.9)
- **ตัดช่องกรอกกรัมออก (4.6.8.3)**
- **ปุ่มเดียว (4.6.8.1):** แถบรอบเหลือปุ่มเดียว **"เสร็จแล้ว ✓"** · การข้ามรอบย้ายไปอยู่ในแผนให้อาหาร ("วันนี้ไม่ให้อาหาร") กับถามย้อนหลัง (ข้อถัดไป)
- **ลืมปิดรอบ (4.6.8.2.2):** ถึงรอบใหม่แล้วรอบเก่ายังเปิดอยู่ → **ปิดรอบเก่าให้เอง** (ตัวที่ไม่ได้บันทึก = กินหมด) แล้วขึ้นการ์ดถามครั้งเดียว: "รอบวันจันทร์ที่ 3 พ.ย. ปิดให้แล้ว (นับว่ากินหมดทุกตัว) — [ถูกต้อง] [แก้ย้อนหลัง] [วันนั้นไม่ได้ให้อาหาร]" · วันที่ไม่ปนกันอีก เพราะเปิดได้ทีละรอบเสมอ
- **บันทึกแค่ตัวที่มีปัญหา (4.6.8.2.3):** ทุกตัวเริ่มที่ "กินหมด" แตะเฉพาะตัวที่ ไม่กิน / กินน้อย แล้วกด "เสร็จแล้ว" — 300 กล่องก็แตะแค่ไม่กี่ตัว
- **โหมดเสียงนำทาง 🔊 (4.6.8.2.1):** จอเต็ม ตัวหนังสือใหญ่บอกกล่องที่ต้องไป ระบบพูดเอง เช่น "กล่อง A1 ปลา 1 ชิ้น รอบก่อนกินน้อย" → "กล่อง A2 ปลา 1 ชิ้น" · ข้ามกล่องว่างให้เอง · เรียงตามผังจริง (ด้านหน้าก่อน แล้วด้านหลัง) · ปรับความเร็วพูด + ระยะเวลาก่อนไปกล่องถัดไปได้ (หรือแตะตรงไหนก็ได้บนจอ = ถัดไป) · **จอไม่ดับ** (Wake Lock) · ตอนเก็บเศษใช้โหมดเดียวกัน: ระบบพูดชื่อกล่อง ผู้ใช้แตะปุ่มใหญ่ "ไม่กิน"/"กินน้อย" ถ้าไม่แตะ = กินหมด
  - เทคนิค: ใช้ **Web Speech API (`speechSynthesis`, th-TH)** ที่มีในเบราว์เซอร์อยู่แล้ว ฟรี มีเสียงไทยทั้ง Android และ iPhone → **ทดสอบบนมือถือคุณก่อนเป็นอย่างแรกของเฟสนี้** ถ้าเสียงไม่มีหรือฟังไม่รู้เรื่อง ค่อยเปลี่ยนไปใช้เสียงจาก Cloud TTS (มีค่าใช้จ่ายนิดหน่อย)
  - เสริมทีหลัง: กดปุ่มหูฟังบลูทูธเพื่อไปกล่องถัดไป (Media Session API — ยังใช้ได้ไม่ทุกเครื่อง)
- ซิงค์หลายเครื่องแบบเรียลไทม์เหมือนเดิม (ใช้ `src/lib/realtime.ts` ต่อ)

### 5.6 ขายปูในหน้ากล่องปู (ข้อ 4.14)
- **เหตุผลที่ไม่ได้ใช้ (4.14.1–4.14.2) = อยู่คนละหน้า และไม่เห็นผังกล่อง** → ย้ายการขายมาอยู่**ในหน้ากล่องปู**:
  1. กด "💰 ขายปู" → ผังเข้าโหมดเลือก (แตะกล่อง = ติ๊ก, ชิปกรอง เช่น ไข่ ≥ 80%, ปุ่ม "ช่วยเลือกให้" แบบเดิม) แถบล่าง "เลือก 5 ตัว · 1.8 กก. [ถัดไป]"
  2. ลูกค้า (ค้นหา หรือ **"+ ลูกค้าใหม่" ตรงนั้นเลย** แค่ชื่อ+เบอร์) · ราคา/กก. (ค่าเริ่มต้นตามชนิดปู) → แบ่งราคารายตัวให้เอง แก้ทีละตัวได้ · ⚠ "ปู 3 ตัวยังไม่มีต้นทุน กำไรจะไม่ถูกต้อง [ใส่ต้นทุนเลย]" (4.14.3)
  3. **ใบเสร็จมีรูปปูทุกตัว (4.14.4)** + น้ำหนัก + % ไข่ → [ส่งรูปให้ลูกค้า] (แชร์/คัดลอก/ดาวน์โหลด ใช้ `html2canvas` + `imageShare` เดิม) · เลือก [จองไว้ก่อน] หรือ [ขายแล้ว ✓]
- กล่องที่จองไว้มีป้าย "🔖 คุณสมชาย" · ขายแล้วปูออกจากผัง ลงบัญชีให้เอง
- **ข้อ 4.14.5 (เพิ่มของตรงจุดที่เลือก) ใช้ทั้งระบบ:** component กลาง `SelectOrCreate` — ทุกช่องที่เลือก ลูกค้า / คนขาย / อาหาร / สารปรุงน้ำ / ระบบปู มี "+ เพิ่มใหม่" อยู่ท้ายรายการ

### 5.7 น้ำ (ข้อ 4.10) — อยู่ถัดจากกล่องปูในเมนู
- **เพิ่มแร่ธาตุเองได้ (4.10.2):** ค่าเริ่มต้นมี pH, อัลคาไลน์, Mg, Ca, ความเค็ม, แอมโมเนีย, ไนไตรท์, K · "+ เพิ่มค่าที่วัด" = ชื่อ + หน่วย + **เลือกสีขวด** (ใช้ไอคอนขวดจาก `plugins/waterBottleIcons.ts` เดิม แปลงเป็น SVG ธรรมดา) + เกณฑ์ ต่ำสุด-สูงสุด
- **เทียบสาร + กฎปรุงน้ำในประโยคเดียว (4.10.3):** การ์ดของแต่ละค่ามีประโยคให้เติมช่อง:
  `ถ้า [Mg] ต่ำกว่า [1250] → ใส่ [แมกนีเซียม ▾] [1] [ช้อนแกง ▾] ค่าจะขึ้น [+20]`
  หรือเลือก "แค่เตือน" / "ให้วัดซ้ำ" · เพิ่มสารใหม่ได้ในช่องนั้น (ไม่มีสต็อก) · สูตรเดิม `dose = (เป้าสูงสุด − ค่าตอนนี้) ÷ ผลต่อ 1 หน่วย`
- **บันทึกค่า:** ช่องใหญ่มีไอคอนขวด → ผลขึ้นทันที "✓ ปกติทุกค่า" หรือ "⚠ Mg ต่ำ → ใส่แมกนีเซียม 2 ช้อนแกง [ใส่แล้ว ✓]" · ค่าที่รอบนี้ลืมวัดยังใช้ค่าเดิมเหมือนเดิม (ใช้ลอจิก `mergedLatestValues`)
- **ประวัติ (4.10.4):** การ์ดรายวัน ("วันจันทร์ที่ 3 พ.ย. 69") ชิปสีของแต่ละค่า เขียว=ปกติ แดง=หลุด แตะดูรายละเอียด + กราฟเล็กต่อค่า

### 5.8 บัญชี (ข้อ 4.15, 4.16)
- **ใช้คำง่ายแทนศัพท์บัญชี (4.15.1):**
  - **ต้นทุนปู (ทางตรง)** = ซื้อปู (มาจากล็อต) · อาหาร (มาจากการซื้ออาหาร) · สาร/จุลินทรีย์
  - **ค่าใช้จ่ายฟาร์ม (ทางอ้อม)** = ค่าไฟ · ค่าน้ำ · อุปกรณ์ · ค่าแรง · อื่นๆ
  - **รายรับ** = ขายปู (มาจากการขาย) · อื่นๆ
  - รายการส่วนใหญ่**ลงให้อัตโนมัติ** ผู้ใช้กรอกเองแค่ค่าใช้จ่ายฟาร์ม
- **สรุปกำไรรายล็อต:** "ล็อตวันเสาร์ที่ 8 พ.ย.: ขายได้ 5,200 − ค่าปู 3,000 − อาหาร+ค่าฟาร์ม (ส่วนของล็อตนี้) ~600 = **กำไร 1,600 ✅**" + ขายแล้ว 8 / ตาย 1 / ยังเลี้ยง 1 · ระบบแบ่งค่าอาหารและค่าฟาร์มให้แต่ละล็อตเองตามจำนวนวันที่ปูอยู่ในฟาร์ม (ไม่โชว์สูตรให้ผู้ใช้เห็น) · มีสรุปรายเดือนด้วย
- **ตัวช่วยคิดค่าไฟ (4.15.2):** เลือกอุปกรณ์จากปุ่ม (ปั๊มน้ำ, ปั๊มลม, ไฟ UV, ชิลเลอร์ …) × จำนวน → มีค่าวัตต์เฉลี่ยใส่ไว้ให้ (รู้ก็แก้ได้) × ชั่วโมงต่อวัน (ค่าเริ่มต้น 24) × ค่าไฟต่อหน่วย (ค่าเริ่มต้น ~4.5 บาท แก้ได้) → "≈ 263 บาท/เดือน" แล้วลงบัญชีให้ทุกเดือนเอง · ตัวเลขเริ่มต้นจะตรวจอีกรอบตอนลงมือทำ และติดป้ายว่าเป็นค่าประมาณ
- **รายงาน (4.16):** ลบหน้ารายงานเดิมทั้งหมด (ต้นทุนดำเนินการ, ตารางเรทไซส์ …) → เหลือ "รายงานบัญชี" เลือกเดือน/ช่วงวัน + **ดาวน์โหลด Excel** (ใช้ไลบรารี `xlsx` เดิม)

### 5.9 หน้าแรกแบบเลือกได้ + วิเคราะห์อาหาร (ข้อ 4.3, 4.8, 5.3)
- หน้าแรกประกอบจากการ์ด: งานวันนี้ · สถานะน้ำ · ปูพร้อมขาย · กำไรเดือนนี้ · อาหารพออีกกี่รอบ · ปูถึงรอบเช็ค · ล็อตยังไม่ใส่ราคา · วิเคราะห์อาหาร · อากาศ · ประกาศ · เริ่มต้นใช้งาน
- **หน้าเลือกแบบ:** 3 แบบสำเร็จรูป (เน้นงานวันนี้ / เน้นการขายและเงิน / เน้นการเลี้ยง) + เปิด/ปิด/เรียงการ์ดเองได้ · จำไว้ต่อผู้ใช้
- **วิเคราะห์อาหารแบบใหม่ (4.8):** เลิกนับเป็นรอบ เพราะเก็บอาหารเป็นรายตัวแล้ว · คำถามที่ตอบ: "**อาหารไหนทำให้ไข่ขึ้นเร็วกว่า**" และ "**ปูกินอะไรหมดมากกว่า**" · วิธีคิด: ช่วงระหว่างการเช็คไข่ 2 รอบของปูแต่ละตัว → % ไข่ที่ขึ้นต่อสัปดาห์ + สัดส่วนมื้อที่กินปลา/หอยในช่วงนั้น → จัดกลุ่ม "กินปลาเป็นหลัก (≥70%)" / "กินหอยเป็นหลัก" / "ผสม" → สรุปเป็นประโยค เช่น "ปูที่กินหอยเป็นหลัก ไข่ขึ้นเร็วกว่า ~4%/สัปดาห์" · ถ้าข้อมูลยังไม่พอ (ฝั่งละไม่ถึง 5 ช่วงจากปู 3 ตัว) บอกตรงๆ ว่ายังสรุปไม่ได้ · การทดลอง "ปลา 20 ตัวแรก หอย 20 ตัวหลังในรอบเดียวกัน" แบบที่คุณยกมาคือแบบที่ได้ผลชัดที่สุด
